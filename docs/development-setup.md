# Rooman Billing - Development Setup

Everything below runs from the **repository root** unless a `cd` is shown. The backend is a
package imported as `backend.app`, and `pytest.ini` / `backend/alembic.ini` are written for that.

## Prerequisites

- Python 3.12 (`python3 --version`)
- Node.js 22 LTS and npm 10 (Node 20 works too)
- Docker with Compose v2 (for PostgreSQL 16; optional - see the SQLite fallback)
- Git

## 1. Clone and branch

```bash
git clone <repo-url> rooman-billing
cd rooman-billing
git checkout -b feature/<short-name>
```

Work on feature branches and open pull requests into `main`; CI (`.github/workflows/ci.yml`) runs
the backend tests on PostgreSQL, applies the migrations, type-checks and builds the frontend and
builds both Docker images.

## 2. Database

```bash
docker compose up -d          # postgres:16-alpine on localhost:5432
docker compose ps             # wait until db is "healthy"
```

Defaults: database `rooman_billing`, user `postgres`, password `postgres`. Data lives in the
`postgres_data` volume; `docker compose down -v` wipes it.

No Docker? Set `DATABASE_URL=sqlite:///./dev_rooman_billing.db` in `backend/.env`. The whole
application works on SQLite for development; only production forbids it.

## 3. Backend

```bash
python3 -m venv backend/venv
source backend/venv/bin/activate          # Windows PowerShell: backend\venv\Scripts\Activate.ps1
pip install -r backend/requirements.txt

cp backend/.env.example backend/.env      # edit if your DB differs
alembic -c backend/alembic.ini upgrade head
uvicorn backend.app.main:app --reload --port 8000
```

- Swagger UI: http://localhost:8000/api/v1/docs (ReDoc at `/api/v1/redoc`)
- Health: http://localhost:8000/api/v1/health
- Integrations status: http://localhost:8000/api/v1/meta/integrations

Settings are read from the environment, then `.env` at the repo root, then `backend/.env`
(later wins) - see `backend/app/core/config.py`. `ALLOWED_ORIGINS` accepts a JSON array or a
comma-separated list. In development the in-process scheduler is on (`SCHEDULER_ENABLED=true`),
which is what you want with a single `uvicorn` process.

### Migrations

```bash
# after changing models under backend/app/models
alembic -c backend/alembic.ini revision --autogenerate -m "add customer notes"
alembic -c backend/alembic.ini upgrade head
alembic -c backend/alembic.ini downgrade -1        # undo the last one
alembic -c backend/alembic.ini history
```

Review autogenerated files before committing - enum and server-default changes often need manual
edits. Never edit a migration that has already shipped; add a new one.

### Tests

```bash
pytest                       # SQLite file under backend/tests, created and deleted automatically
pytest backend/tests/test_invoices.py -k totals -vv
```

Run the same suite on PostgreSQL (what CI does):

```bash
docker compose exec db psql -U postgres -c 'CREATE DATABASE rooman_test;'
TEST_DATABASE_URL=postgresql+psycopg://postgres:postgres@localhost:5432/rooman_test pytest
```

`backend/tests/conftest.py` forces `ENVIRONMENT=test`, disables the scheduler, blanks the
Razorpay/SMTP settings and relaxes the auth rate limit before the app is imported. The `tenant`
fixture gives you a fresh organization with an owner plus helpers for other roles, customers and
plans.

### Email locally

Leave `SMTP_HOST` empty and invitation / reset links appear in the API response and UI. To see
real emails, run Mailpit and point the backend at it:

```bash
docker run -d --name mailpit -p 1025:1025 -p 8025:8025 axllent/mailpit
# backend/.env
SMTP_HOST=localhost
SMTP_PORT=1025
SMTP_USE_TLS=false
```

Inbox at http://localhost:8025.

### Razorpay locally

Use **Test mode** keys from the Razorpay dashboard in `backend/.env`. Checkout on the hosted
payment page works from `localhost`. Webhooks need a public URL: expose port 8000 with a tunnel
(e.g. `cloudflared tunnel --url http://localhost:8000` or ngrok), register
`https://<tunnel>/api/v1/webhooks/razorpay` as a test-mode webhook and put its secret in
`RAZORPAY_WEBHOOK_SECRET`. Without a tunnel the verify step on the payment page is enough to mark
invoices paid; the webhook is a redundancy path.

`RAZORPAY_*` are the keys tenant payments use (when an organization has not connected its own
account). Rooman Billing's **own** account, which organizations pay for a Rooman plan, is
configured separately with `PLATFORM_RAZORPAY_KEY_ID` and `PLATFORM_RAZORPAY_KEY_SECRET` (Test
Mode keys locally, also in `backend/.env`). Set both or neither; they must differ from `RAZORPAY_*`
and are never used for tenant payments or sent to the browser.

#### Sandbox test plan (Test Mode purchase without publishing a commercial plan)

The plan catalog ships one test-only plan, `sandbox_foundation` ("Sandbox Test Plan (Foundation)",
₹1/month, Foundation bundle only, 3 seats). It is never in the public catalog and can be bought only when
**all** of these hold (checked on every request):

1. `PLATFORM_SANDBOX_PLANS_ENABLED=true` in `backend/.env` (default `false`);
2. `ENVIRONMENT` is `development` or `test` (production and staging refuse it whatever the flag says);
3. `PLATFORM_RAZORPAY_KEY_ID` is a Test Mode key (`rzp_test_...`); Live Mode keys never sell it;
4. `PLATFORM_RAZORPAY_WEBHOOK_SECRET` is set (plan checkout of any kind refuses to start without it).

The platform webhook: expose port 8000 with a tunnel, register
`https://<tunnel>/api/v1/webhooks/razorpay-platform` in the Razorpay dashboard **in Test Mode**, on
Rooman's own account, with the events `subscription.authenticated`, `subscription.activated`,
`subscription.charged`, `subscription.pending`, `subscription.halted`, `subscription.cancelled` and
`subscription.completed`, and a newly generated secret of its own. Put that secret in
`PLATFORM_RAZORPAY_WEBHOOK_SECRET` (never the API key secret and never `RAZORPAY_WEBHOOK_SECRET`; the API
refuses to start if they are equal) and restart the backend. The Subscription page (Settings ->
Subscription) then shows the plan under "TEST MODE - NOT A COMMERCIAL OFFER" for the Owner to buy with a
Razorpay test card; the plan starts only after Razorpay confirms the payment (callback or webhook).

### Running the scheduler manually

Owners can trigger one pass with `POST /api/v1/admin/jobs/run` (via Swagger). Use it to test
renewals and dunning without waiting for the interval.

## 4. Frontend

```bash
cd frontend
npm ci
cp .env.example .env         # VITE_API_BASE_URL=http://localhost:8000
npm run dev                  # http://localhost:5173
```

`vite.config.ts` proxies `/api` to `http://localhost:8000`, so you may also set
`VITE_API_BASE_URL=` (empty) to exercise the same-origin mode used by the production image.

Checks before pushing:

```bash
npx tsc --noEmit
npm run build                # tsc && vite build -> frontend/dist
```

## 5. Building the images locally

```bash
docker build -f backend/Dockerfile -t rooman-billing-api .        # context = repo root
docker build -t rooman-billing-web ./frontend                     # context = frontend/
```

Or bring up the whole production stack against a throwaway `.env.production`
(see [`deployment.md`](deployment.md)).

## 6. Conventions

- Money is `Decimal`; never introduce floats in services or schemas. Use `services/money.py`.
- Every repository query filters by `organization_id`; every mutation writes an audit row.
- Endpoints, schemas and services follow `docs/api-contract.md` exactly - update the contract
  first when a change is needed.
- Frontend: no direct axios calls in components; add/extend the typed service instead.
- Never commit `.env`, `.env.production` or `backend/.env` (all git-ignored). Run `pytest` and
  `npm run build` before opening a PR.
